# Parsec-to-OpenStream feature matrix

Updated 2026-09-12 for Task 7 after inspecting the platform policy and host
adapters. This matrix is intentionally evidence-based. Each device feature
separates protocol support, implementation, runtime availability, and
hardware validation. A feature is advertised only when protocol support,
implementation, and the bounded runtime probe all succeed. Hardware-tested is
reported separately and is never inferred from a unit test or compile check.

| Capability | Supplied/local Parsec evidence | OpenStream state | Evidence/status |
|---|---|---|---|
| HTTPS/API control plane | Kessel/API strings and official connectivity page | Implemented with self-hosted REST service | `openstream-signal-server`; live health/session/revoke check passed |
| WebSocket signaling | Role URL/action strings and official connection sequence | Implemented with role-scoped bearer tokens, typed bounded envelopes, bounded queues, and reliable capability establishment | `openstream-client-core`, signal-server tests |
| STUN, UPnP, and simultaneous UDP | STUN/UPnP/hole-punch strings and official port requirements | Implemented for direct nomination, opt-in SSDP/SOAP IGD mapping, optional standards-based ICE, authenticated direct keepalive, and finite direct-path liveness | UPnP parser/escaping tests, transport/client-core tests, local full-ICE loopback passed; physical-router/public-network matrix remains open |
| Relay fallback | Official docs describe a Parsec Relay that forwards UDP; its TURN semantics are not established | Application-owned opaque relay plus optional standards-based TURN via `webrtc-ice`, now with session-scoped service credentials | forced-relay and local full-ICE tests passed; `/turn` issuance tests passed; external coturn live run open |
| Native media transport | Parsec documents proprietary BUD over UDP, DTLS 1.2/OpenSSL | OpenStream uses a separate versioned `OS` UDP format with X25519/AES-256-GCM | protocol tamper/replay/size tests; intentionally not stock-compatible |
| Video | H.264/H.265, hardware encode/decode, low-buffer behavior observed | H.264/H.265 negotiation, bounded fragmentation, FFmpeg host/decode path, NVENC/VAAPI/libx264-5 profiles with detection, negotiated 10-bit/4:4:4 pix-fmt gating, ACK-driven rolling-restart rate control | H.264/H.265 loopbacks passed; in-process native encoders open |
| Adaptive bitrate | BUD public description says it adapts before queues grow; exact controller is proprietary | Bounded `FA` assembled-frame ACKs; native Linux reduces/ramps the lowlat encoder ceiling from ACK age and explicit client-reported gaps; FFmpeg startup rate remains fixed | media controller tests and native hook compile; long-run network/encoder acceptance open |
| Audio | Opus, 48 kHz stereo, approximately 20 ms browser samples | Opus packetization, jitter buffer, PLC, FFmpeg and Linux audio host paths | audio loopback passed; native mobile/device acceptance open |
| Keyboard/pointer/wheel | HID/input strings and browser input channel | Fixed 32-byte `OI` envelope and desktop keyboard, pointer, and wheel adapters; Linux uinput, Windows SendInput, and macOS CoreGraphics are explicit-policy and runtime-probe gated | protocol and host tests pass; hardware-tested is not recorded; Linux also requires `/dev/uinput` access |
| Pen/tablet | HID/input strings and enhanced pen settings | OI pen framing exists, but the full tablet adapter does not preserve pressure, tilt, rotation, and proximity semantics; pen capability is not advertised | pointer fallback is not tablet support; implementation and hardware validation remain open |
| Gamepad | Gamepad API, XInput/ViGEm/uinput evidence | OI gamepad events and desktop client input exist; Linux host uinput gamepad and force feedback are implemented only with `OPENSTREAM_ENABLE_INPUT=1`, `OPENSTREAM_GAMEPAD=1`, and a successful uinput probe; Windows/macOS host virtual gamepads are not implemented and never advertised | Linux hardware/gamepad acceptance is open; Windows/macOS virtual gamepad work remains unimplemented |
| Linux hosting | Linux artifact sets `hosting_supported=false` and lacks host capture/encoder evidence; Parsec's public host requirements call for hardware encoding | Native lowlat Linux adapter with DRM/KMS scanout capture, device-buffer export/conversion, and uinput; X11 setup/enumeration for diagnostics; external FFmpeg X11/PipeWire capture profiles; HW detection; user+system systemd units; guest-mic seat enablement | `openstream-linux-host --preflight` is the readiness check; input capability is withheld when uinput is absent or inaccessible; Ubuntu 22.04+ 1080p60 hardware gate remains open |
| Windows hosting | Windows artifact has DXGI/NVENC/AMF/MFX indicators | External FFmpeg host adapter with explicit `gdigrab` profile and basic SendInput; no virtual gamepad, tablet, virtual microphone, virtual display, or USB adapter is advertised | native Desktop Duplication/encoder adapters open; physical input acceptance is open |
| macOS hosting | macOS artifact has ScreenCaptureKit/VideoToolbox/Metal indicators | External FFmpeg host adapter with explicit `avfoundation` profile and basic CoreGraphics input; no virtual gamepad, tablet, virtual microphone, virtual display, or USB adapter is advertised | native capture/encode/render adapters open; physical input acceptance is open |
| Desktop clients | Native platform render/input paths observed | Software window client plus optional wgpu texture presentation (Metal, Vulkan/OpenGL, Direct3D12), validated BGRA presents, paced re-presents, windowed/borderless/fullscreen, hotkeys, metrics overlay line, mic capture, 10-bit/4:4:4 opt-ins | Exact D3D11 semantics, GPU/driver matrix, long-run device acceptance, and native audio remain open |
| Android client | Supplied XAPK is client-only; MediaCodec is the intended boundary | Kotlin/JNI shell plus pause/resume lifecycle, thermal listener, release signing template, host-checkable acceptance harness | on-device MediaCodec runs and signed store APK open |
| iOS client | Supplied/current Parsec support does not include iOS | Swift client-only layer plus foreground/background pause, thermal reporting, acceptance harness | Xcode signing/device validation open |
| Multi-monitor/virtual displays | Parsec strings expose virtual monitor/VDD/VUSB features | Bounded `MD`/`MS` messages, RandR enumeration, fail-closed `OPENSTREAM_DISPLAY`, selected-output metadata, desktop Ctrl+Alt+PageUp/PageDown picker, and bounded live switching in Linux X11/FFmpeg plus native DRM/KMS hosts; Xvfb helper | Existing-monitor discovery and selection can be advertised where implemented; OS-level virtual display creation is not implemented and never advertised; physical multi-monitor gate remains open |
| Clipboard | Feature strings and package dependencies observed | Chunked clipboard with direction/approval/conflict/privacy policy and platform helper adapters, subject to explicit policy and helper availability | protocol and adapter tests pass; hardware-tested and runtime acceptance remain open |
| Guest microphone | Feature strings and package dependencies observed | Opus guest-microphone transport, bounded decode, and optional raw PCM verification sink; this is not an OS virtual microphone endpoint | decoder availability and `OPENSTREAM_MIC=1` gate the negotiated capability; virtual microphone is not implemented and never advertised |
| USB passthrough | Parsec strings expose LibUSB/YubiKey passthrough | Protocol support is explicitly unsupported; no privileged USB or HID passthrough adapter exists and the capability is never advertised | Requires an isolated privileged-device design |
| Auth, permissions, metrics, recovery | Teams/ownership/whitelist/elevation and metrics strings observed | Admin token, TTL/revocation, 60/min creation limit, guest admission with parking/kick by non-secret guest id, signed/pinnable peer identity, host permission policy, RTT/loss overlay metrics, reconnect backoff | per-user account policy/UI and simultaneous media fan-out open |

## Interpretation

The matrix confirms that the current implementation is a functional,
self-hosted OpenStream development stack with Linux hosting, not a finished
all-feature Parsec replacement. It also confirms why stock Parsec clients are
not a supported target: OpenStream deliberately does not claim the unverified
BUD/Kessel byte-level and authorization behavior. The remaining unchecked
items are tracked in [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md).
